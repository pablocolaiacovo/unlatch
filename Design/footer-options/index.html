Unlatch popover footer: four options

Exploration for issue #13 task T3. Four things now compete for one 372 pt wide footer: the version, Open at Login (#51), Check for Updates / Update Available (T3), and Quit. All screenshots are real captures of the running app (swift run build on macOS 27, real popover, real vibrancy) with a stubbed updater and a faked login item. Light and dark, normal and "update available". Click any strip to see the full popover.

Recommendation: Option C, the "…" menu recommended

Put the version, Check for Updates… and Open at Login in a small ellipsis menu next to Quit. When an update is waiting, the footer shows a blue "Update Available" button on the left and a blue dot on the ellipsis, so the one thing that needs attention is impossible to miss, and the footer is otherwise nearly empty.

Why: it is the only option that does not get more crowded when the next item arrives (it just becomes one more menu row), it has no width problems in other languages, it matches how Itsycal, Maccy and Dropbox-style menu bar apps handle app-level housekeeping, and the menu is a standard AppKit pop-up that VoiceOver and the keyboard already handle. The cost is that Open at Login is now two clicks away; it is a set-once preference, so that is acceptable.

Runner-up: Option B (two rows) if you want every control visible with no menu. It is the safest "nothing hidden" choice and handles long languages, at the price of 26 pt more height on every step. Avoid A (single row): the stress test shows the update button and the version both truncate with an ellipsis, and German or French strings will be worse. D (version as the update link) is the cheapest to build but hides "Check for Updates" behind a label that does not look clickable.

How well-known menu bar apps do it

  • Apple HIG, menu bar extras: keep the extra's own UI minimal, and put infrequent items in a menu. Quit and settings belong in a menu or at the bottom edge; avoid dense multi-control toolbars in a popover.
  • Itsycal, Maccy, Rectangle, Tailscale: a gear or ellipsis at the bottom of the popover opens a menu containing Preferences, Check for Updates, About and Quit.
  • Dropbox, 1Password mini: a bottom bar with one icon-only overflow control; update availability shown by a badge or a banner above it, not by relabeling a footer link.
  • Stats, iStat Menus: a small gear in the corner plus a version/update banner only when relevant.

From general familiarity with these apps; not re-verified against their current builds.

How these were made

Live captures, not renders. Each image is screencapture -R of the popover window rect from CGWindowListCopyWindowInfo filtered by the process id, of the real Unlatch binary built on branch explore/footer-options. A solid colour window behind the popover keeps the backdrop identical in every shot. Dark mode is forced on the app and popover only (system setting untouched). No keystrokes and no clicks were sent: the open menu shots call performClick on the menu button from inside the app. The version is forced to Version 1.1.0 (128), and the stress shots use 0.0.0-abc1234-dirty (999), the long string from T3's acceptance criteria.

The code is exploration only: Sources/Unlatch/Views/FooterVariants.swift (style switch via UNLATCH_FOOTER_STYLE, stub updater, fake login item, capture hooks).
